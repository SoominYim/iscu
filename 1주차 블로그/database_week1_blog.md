# [데이터베이스] 데이터베이스 학습 (1) - 데이터와 데이터베이스란?

데이터베이스를 배우기 시작하면 제일 먼저 드는 생각이 있다.

그냥 파일로 저장하면 되는 거 아닌가?

프론트에서 API 받아서 화면에 뿌리고, 필요하면 JSON으로 주고받고, 로컬에 잠깐 저장해도 돌아가는 경우가 많다. 그래서 처음에는 데이터베이스가 그냥 "데이터 넣어두는 큰 창고" 정도로 느껴진다.

근데 조금만 생각해보면 그걸로 안 끝난다. 데이터는 종류도 다르고, 의미도 다르고, 여러 사람이 동시에 쓰기 시작하는 순간부터 관리 방식이 훨씬 중요해진다. 이번 글에서는 1주차에서 배운 데이터 유형, 데이터와 정보의 차이, 정보처리, 정보시스템과 데이터베이스, 그리고 데이터베이스의 정의와 특징까지 정리해보려고 한다.

## 데이터 유형

데이터라고 해서 다 같은 데이터는 아니다. 어떤 형태로 저장되느냐, 어떤 성질을 가지느냐에 따라 나눠 볼 수 있다.

### 형태에 따른 분류

#### 정형 데이터

정형 데이터는 행과 열처럼 표 형태로 규칙적으로 정리된 데이터다. 가장 익숙한 예시는 고객 정보, 판매 기록, 주문 목록 같은 것들이다. 즉, 컬럼이 정해져 있고 그 틀에 맞춰 값이 들어간다.

이런 데이터는 검색, 정렬, 집계가 편하다. 그래서 관계형 데이터베이스와도 잘 어울린다.

#### 반정형 데이터

반정형 데이터는 어느 정도 규칙은 있지만 완전히 표처럼 딱 고정된 형태는 아닌 데이터다. 대표적으로 JSON, XML, HTML 메타데이터 같은 것들이 있다.

개발하면서 제일 자주 체감되는 게 아마 JSON일 것 같다. 키와 값이라는 구조는 있지만, 모든 데이터가 똑같은 필드를 가지는 건 아니기 때문이다. 즉, 질서는 있는데 완전히 정형화된 건 아니다.

#### 비정형 데이터

비정형 데이터는 규칙 없이 자유로운 형태로 저장된 데이터다. 사진, 영상, 음성 파일, SNS 글, 문서 파일 같은 것들이 여기에 들어간다.

이 데이터들은 내용 자체는 굉장히 풍부하지만, 표처럼 바로 분석하기는 어렵다. 그래서 별도의 전처리나 분류 과정이 필요한 경우가 많다.

### 특성에 따른 분류

형태 말고 성질로도 나눌 수 있다.

#### 범주형 데이터

범주형 데이터는 그룹이나 종류를 구분하는 데이터다.

명목형은 순서가 없다. 예를 들면 성별, 혈액형, 취미 같은 값들이다.

순서형은 순서는 있지만 간격의 크기까지 의미 있진 않다. 예를 들면 학점, 직급, 만족도 같은 값들이다.

#### 수치형 데이터

수치형 데이터는 숫자로 표현되는 값이다.

이산형은 정수로 셀 수 있는 값이다. 고객 수, 판매량, 댓글 수처럼 "몇 개"를 나타낼 때 많이 쓴다.

연속형은 소수점까지 포함할 수 있는 연속적인 값이다. 키, 몸무게, 온도 같은 데이터가 대표적이다.

처음에는 분류가 좀 귀찮아 보이는데, 이걸 구분해두면 나중에 저장 방식이나 분석 방식이 왜 다른지도 같이 이해된다.

## 데이터와 정보는 다르다

이 부분은 생각보다 중요한데, 데이터와 정보는 같은 말이 아니다.

데이터는 사실이나 값 그 자체다. 예를 들면 `22, 23, 24, 25` 같은 온도 측정값, 혹은 `예`, `아니오`, `모름` 같은 설문 응답이 데이터다.

반면 정보는 그 데이터를 분석하고 가공해서 의미를 부여한 결과다. 예를 들면 "지난 일주일 평균 온도는 24도였다", "응답자의 70%가 예라고 답했다" 같은 문장은 정보다.

즉, 데이터가 원재료라면 정보는 그걸 해석해서 바로 쓸 수 있게 만든 결과물이라고 보면 된다.

이 차이를 이해하면 왜 데이터를 그냥 쌓아두기만 해서는 안 되는지도 바로 연결된다. 중요한 건 저장 자체보다, 그 데이터를 필요한 순간에 의미 있는 정보로 바꿔 쓰는 일이다.

## 정보처리란 무엇일까

그렇다면 데이터를 정보로 바꾸는 과정은 뭘까.

이게 바로 정보처리다.

정보처리는 데이터를 수집하고, 저장하고, 조작하고, 변환하고, 전송해서 유용한 정보로 바꾸는 과정이다. 흐름으로 보면 보통 `입력 -> 처리/저장 -> 출력` 형태로 이해하면 편하다.

일상에서도 정보처리는 계속 일어난다. 운전할 때 신호등을 보고 판단해서 움직이는 것도 일종의 정보처리이고, 비즈니스에서는 판매 데이터를 모아서 월간 보고서를 만드는 것도 정보처리다. 프로그래밍에서는 사용자가 입력한 값을 계산해서 결과를 보여주거나, 웹 크롤링으로 수집한 정보를 분석한 뒤 데이터베이스에 저장하는 일도 정보처리라고 볼 수 있다.

여기서 한 가지 같이 기억할 만한 건, 정보를 해석할 때 인과관계를 너무 쉽게 단정하면 안 된다는 점이다.

예를 들어 기온이 올라가면 아이스크림 판매량이 늘 수는 있다. 그런데 아이스크림 판매량이 기온을 올리는 건 아니다. 데이터를 보고 관계를 찾는 것도 중요하지만, 그 관계를 어떻게 해석하느냐는 별개의 문제다.

이 부분은 데이터베이스보다 통계나 분석 쪽에 더 가깝긴 하지만, 데이터를 다룰 때 기본적으로 가져가야 할 태도라고 생각한다.

## 정보시스템과 데이터베이스

이쯤 되면 비슷한 단어들이 슬슬 헷갈린다. 정보시스템이랑 데이터베이스는 같은 걸까?

결론부터 말하면, 같지는 않다.

정보시스템은 조직의 정보 처리와 관리에 관련된 전반적인 시스템을 말한다. 쉽게 말해 데이터를 받아서 처리하고, 필요한 결과를 만들어내고, 업무를 지원하는 큰 틀이다.

예를 들면 회계정보 시스템, 인사관리 시스템 같은 것들이 정보시스템이다.

그렇다면 데이터베이스는?

데이터베이스는 그 정보시스템 안에서 데이터를 저장하고 관리하는 핵심 부분이라고 보면 된다.

예를 들어 회사의 고객 정보를 관리하는 고객관리 시스템이 있다고 하면, 그 시스템 전체는 정보시스템이고, 그 안에서 고객 정보, 주문 내역, 연락처를 모아 저장하는 부분이 데이터베이스다.

즉, 정보시스템이 "일을 처리하는 전체 시스템"이라면, 데이터베이스는 그 안에서 "데이터를 맡아 관리하는 저장소"에 가깝다.

## 데이터베이스의 정의

교안에서 데이터베이스는 특정 조직의 여러 사용자가 공유하여 사용할 수 있도록 통합해서 저장한 운영 데이터의 집합이라고 설명한다.

처음 보면 단어가 좀 어렵다. 근데 이 문장을 끊어서 보면 훨씬 이해가 쉽다.

### 통합된 데이터

데이터가 여기저기 흩어져 있지 않고 한데 모여 관리된다는 뜻이다. 중복을 줄이고, 같은 내용을 부서마다 따로따로 관리해서 생기는 혼란을 줄이는 방향이다.

### 저장된 데이터

말 그대로 컴퓨터가 사용할 수 있는 형태로 저장된 데이터라는 뜻이다. 머릿속에 있는 정보가 아니라, 실제로 시스템 안에 기록되어 있어야 한다.

### 운영 데이터

실무에서 실제 운영에 사용되는 데이터라는 뜻이다. 시험용, 임시용 데이터가 아니라 업무를 돌리는 데 필요한 데이터라는 말이다.

### 공용 데이터

여러 사용자나 여러 응용 프로그램이 함께 사용할 수 있는 데이터라는 뜻이다. 혼자만 보는 파일이 아니라, 조직 안에서 같이 써야 하는 데이터라는 점이 중요하다.

결국 데이터베이스는 그냥 데이터 모아둔 파일이 아니라, 여러 사람이 함께 쓰기 위해 정리되고 저장된 운영 데이터의 묶음이라고 이해하면 훨씬 자연스럽다.

## 데이터베이스의 특징

데이터베이스는 몇 가지 특징 때문에 일반 파일 저장과 다르게 느껴진다.

### 실시간 접근성

사용자의 요구에 맞춰 실시간으로 처리하고 응답할 수 있어야 한다. 온라인 뱅킹이나 항공권 예약 시스템이 대표적이다.

버튼 눌렀는데 몇 시간 뒤에 결과가 반영되면 아무도 못 쓴다. 데이터베이스는 지금 필요한 데이터를 지금 꺼내 쓸 수 있어야 한다.

### 내용에 의한 참조

데이터를 찾을 때 저장 위치를 직접 아는 게 아니라, 내용으로 찾는다. 예를 들어 이름으로 고객을 검색하거나, 특정 단어가 포함된 문서를 찾는 식이다.

이게 당연해 보이지만 생각해보면 꽤 큰 차이다. 사용자는 "몇 번째 파일의 몇 번째 줄"을 찾고 싶은 게 아니라, "홍길동 주문 내역"처럼 의미를 기준으로 데이터를 찾고 싶어 한다.

### 동시 공유

같은 데이터를 여러 사용자가 동시에 사용할 수 있다. 온라인 쇼핑몰에서 여러 사람이 동시에 상품을 조회하고 주문하는 상황이 여기에 해당한다.

이 특징이 중요해지는 순간이 바로 충돌 문제다. 여러 명이 동시에 접근하면 누가 먼저 수정했고, 어떤 값이 최종값이 되어야 하는지 관리가 필요해진다. 그래서 데이터베이스는 그냥 저장만 하는 게 아니라, 동시에 써도 버틸 수 있어야 한다.

### 계속적인 변화

데이터베이스의 데이터는 한 번 넣고 끝나는 게 아니다. 새로운 데이터가 들어오고, 기존 데이터가 수정되고, 필요 없어진 데이터는 삭제된다.

쇼핑몰 재고, 예약 시스템 좌석 정보, 뉴스 사이트 기사 목록처럼 현실 데이터는 계속 바뀐다. 그래서 데이터베이스는 변화하는 데이터를 현재 상태에 맞게 유지해야 한다.

## 그래서 왜 데이터베이스를 배우는 걸까

1주차를 정리하면서 느낀 건, 데이터베이스는 단순히 "어디 저장하지?"의 문제가 아니라는 점이다.

어떤 데이터인지 구분할 수 있어야 하고, 그 데이터가 정보로 어떻게 바뀌는지도 이해해야 하며, 여러 사람이 동시에 쓰는 환경에서 어떻게 안정적으로 관리할지도 생각해야 한다.

특히 정형, 반정형, 비정형 데이터 구분은 요즘처럼 JSON도 많이 쓰고, 이미지나 문서 데이터도 흔한 환경에서는 더 현실적으로 와닿는다.

그리고 데이터베이스의 정의에 들어 있는 통합, 저장, 운영, 공용 이 네 단어는 꽤 자주 다시 만나게 될 것 같다.

처음에는 그냥 외우는 말처럼 보였는데, 결국 데이터베이스가 왜 필요한지를 거의 그대로 설명해주는 단어들이기 때문이다.

## 마치며

이번 1주차는 SQL을 바로 막 치는 시간은 아니었다. 대신 그 전에, "우리가 대체 뭘 저장하고 있는가", "그걸 왜 데이터베이스라고 부르는가"를 정리하는 시간에 더 가까웠다.

정리하면 이렇다.

데이터는 원재료이고, 정보는 가공된 결과다. 정보처리는 그 둘을 이어주는 과정이다. 그리고 데이터베이스는 그 데이터를 여러 사용자가 함께 쓰기 좋게 저장하고 관리하는 구조다.

기초 개념이라서 가볍게 보일 수 있는데, 오히려 이런 부분이 뒤로 갈수록 계속 기준점이 될 것 같다.
