# [객체지향프로그래밍] 객체지향프로그래밍 학습 (1) - 자바와 객체지향은 왜 같이 배울까?

객체지향프로그래밍이라고 하면 보통 `클래스`, `상속`, `캡슐화` 같은 단어부터 떠오른다. 이름만 보면 바로 문법부터 복잡하게 들어갈 것 같고, 실제로도 처음 들으면 조금 긴장되는 과목이 맞다.

그런데 1주차 내용을 정리해보니 의외로 시작점은 문법 암기보다 더 앞에 있었다. 자바가 어떤 언어인지, 왜 객체지향 언어라고 부르는지, 프로그램은 어떤 과정을 거쳐 실행되는지, 그리고 개발환경은 왜 따로 설정해야 하는지를 먼저 잡아주는 시간에 가까웠다.

이번 글에서는 1주차에서 다룬 내용을 기준으로 자바와 객체지향의 기본 개념, 자바의 특징, JDK와 JVM의 역할, 개발환경 구축, 그리고 자바 프로그램의 기본 구조까지 한 번에 정리해보려고 한다.

## 객체지향프로그래밍을 배우는 이유

처음에는 그냥 "자바 문법 배우는 과목" 정도로 생각하기 쉽다. 그런데 교안을 따라가다 보니 이 과목은 언어 하나를 익히는 걸 넘어서, 프로그램을 어떤 단위로 나누고 어떤 방식으로 관리할지를 배우는 과목에 더 가까웠다.

프로그램이 커질수록 코드가 길어지고, 기능도 많아지고, 사람이 함께 작업하는 일도 늘어난다. 이때 모든 코드를 한 덩어리처럼 다루면 수정도 어렵고 재사용도 힘들어진다. 객체지향은 이 문제를 해결하기 위해 프로그램을 역할 단위로 나누고, 각각의 책임을 분리하는 방식이라고 볼 수 있다.

즉 객체지향프로그래밍은 단순히 "문법 스타일"이 아니라 **복잡한 프로그램을 조금 더 다루기 쉽게 만드는 사고방식**에 가깝다.

## 자바란 무엇일까

자바는 대표적인 객체지향 프로그래밍 언어다. 객체의 개념을 중심으로 프로그램을 구성하고, 클래스라는 틀을 통해 데이터와 기능을 함께 묶어 다룬다.

교안에서는 자바를 설명하면서 객체지향 프로그래밍의 핵심 특징도 함께 정리했다. 정리해보면 이렇다.

### 캡슐화와 정보은닉

캡슐화는 객체가 가진 정보와 기능을 하나로 묶는 개념이다. 그리고 정보은닉은 그 안에 있는 정보를 외부에서 마음대로 건드리지 못하게 숨기는 개념이다.

처음엔 두 개가 비슷하게 느껴졌는데, 정리해보면 캡슐화가 "묶는 것"이라면 정보은닉은 "함부로 못 건드리게 막는 것"에 더 가깝다. 결국 둘 다 객체 내부 상태를 보호하고, 필요한 방식으로만 접근하게 만드는 역할을 한다.

### 추상화

추상화는 여러 대상에서 공통된 부분만 뽑아내어 중요한 특징으로 정리하는 것이다. 프로그램을 만들 때 모든 세부사항을 처음부터 다 드러내기보다, 필요한 핵심 개념만 먼저 잡는 이유도 여기에 있다.

예를 들어 학생 관리 프로그램을 만든다고 하면, 학생이라는 대상을 표현할 때 이름, 학번, 전공 같은 핵심 정보부터 정리하지 머리카락 길이나 오늘 입은 옷까지 다 모델링하지는 않는다. 이런 식으로 중요한 속성과 기능만 남기는 게 추상화다.

### 상속

상속은 이미 만들어진 클래스의 속성과 기능을 새로운 클래스가 이어받는 것이다. 그래서 비슷한 기능을 가진 클래스를 만들 때 매번 처음부터 다시 작성하지 않아도 된다.

이 개념은 "재사용"이라는 장점 때문에 자주 강조되지만, 실제로는 구조를 정리하는 역할도 크다. 공통 기능은 부모 클래스에 두고, 각자 다른 부분만 자식 클래스에서 확장하면 코드 흐름이 훨씬 깔끔해진다.

### 다형성

다형성은 같은 이름의 기능이라도 상황이나 객체에 따라 다르게 동작할 수 있게 하는 특징이다.

처음엔 추상화나 상속보다 더 어렵게 느껴졌는데, 결국 핵심은 하나였다. **겉으로는 같은 메시지를 보내더라도 실제로 어떤 객체가 받느냐에 따라 다른 동작이 가능하다**는 점이다. 객체지향이 유연하다고 말하는 이유도 여기에 있다.

## 자바의 특징은 뭐가 다를까

교안에서는 자바의 특징도 꽤 강조했다. 단순히 "객체지향 언어다"에서 끝나는 게 아니라, 자바가 왜 오래 살아남았는지를 설명하는 포인트들이 있었다.

### 컴파일 언어이면서 JVM 위에서 동작한다

자바는 소스 코드를 작성한 뒤 바로 실행하는 방식이 아니라 먼저 컴파일을 거친다. 그런데 여기서 바로 기계어로 바뀌는 게 아니라 **바이트코드**로 변환되고, 이 바이트코드를 **JVM(Java Virtual Machine)** 이 실행한다.

그래서 자바는 운영체제에 직접 종속되기보다 JVM이 설치된 환경이라면 비교적 동일하게 실행될 수 있다. 이 구조 덕분에 "한 번 작성하면 여러 환경에서 실행 가능하다"는 자바의 장점이 나온다.

### 플랫폼 독립성

C나 C++처럼 운영체제에 맞게 다시 컴파일해야 하는 언어와 비교하면, 자바는 운영체제 차이에 덜 묶인다. 윈도우, 유닉스, 리눅스, 맥 같은 다양한 환경에서도 JVM만 갖춰져 있으면 실행이 가능하다.

이 특징은 실무에서도 꽤 큰 장점일 것 같다. 개발하는 환경과 실행하는 환경이 다를 때, 같은 프로그램을 비교적 일관되게 돌릴 수 있기 때문이다.

### 객체지향 언어

자바는 클래스와 객체를 중심으로 프로그램을 구성한다. 그래서 문법을 배우는 것만큼이나 "객체를 어떻게 나눌 것인가", "어떤 책임을 어디에 둘 것인가"가 중요해진다.

처음 자바를 배울 때는 `public static void main` 같은 문장에 시선이 먼저 가지만, 결국 자바를 자바답게 쓰려면 객체지향적 구조를 같이 이해해야 한다는 뜻이기도 하다.

### 멀티스레드 지원과 자동 메모리 관리

자바는 하나의 프로세스 안에서 여러 스레드를 동시에 다루는 프로그래밍을 지원한다. 그리고 메모리 관리도 프로그래머가 일일이 직접 하기보다 가비지 컬렉션을 통해 자동으로 처리해주는 편이다.

물론 자동으로 처리된다고 해서 메모리를 신경 안 써도 되는 건 아니겠지만, 적어도 메모리 해제까지 모두 직접 관리해야 하는 언어에 비하면 진입장벽은 조금 낮아 보인다.

## JDK, JVM, API는 각각 무슨 역할을 할까

개발환경 부분에서 제일 헷갈렸던 건 JDK, JVM, API가 이름은 많이 들어봤는데 막상 뭐가 다른지 한 번에 설명하기 어렵다는 점이었다.

정리하면 이렇게 볼 수 있다.

- `JDK`는 자바 프로그램을 만들기 위한 개발 도구 모음이다.
- `JVM`은 컴파일된 바이트코드를 실행해주는 가상머신이다.
- `Java API`는 자바 개발에 사용하는 라이브러리의 집합이다.

즉, 자바 프로그램을 만들려면 JDK가 필요하고, 실행하려면 JVM이 필요하고, 자바 안에서 제공하는 다양한 기능을 편하게 쓰려면 API를 사용하게 된다.

교안에서 JDK를 `자바 개발도구 + JVM + 자바 API`의 묶음처럼 설명한 부분이 꽤 이해하기 쉬웠다. 결국 JDK를 설치한다는 말은 자바로 개발하고 실행하는 데 필요한 기본 세트를 갖추는 것에 가깝다.

## 개발환경 구축은 왜 중요한가

1주차에서 꽤 많은 비중을 차지한 게 바로 개발환경 구축이었다. JDK 설치, 운영체제 확인, 환경 변수 설정, Eclipse 설치와 실행까지 꽤 실습 중심으로 이어졌다.

처음엔 이런 생각이 들 수도 있다.

"아니 아직 코딩도 안 했는데 설치부터 이렇게 많이 해야 하나?"

근데 생각해보면 당연한 순서이기도 하다. 프로그램을 작성할 도구가 제대로 준비되지 않으면 그 다음 단계로 넘어갈 수가 없기 때문이다.

특히 환경 변수 설정은 그냥 절차 하나가 아니라, 운영체제가 자바 실행 경로를 인식하도록 연결하는 작업이라는 점에서 의미가 있다. `JAVA_HOME`을 잡고 `path`에 경로를 추가하는 과정도 결국 "이 컴퓨터가 자바를 어디서 찾아야 하는지 알려주는 작업"이라고 이해하면 좀 덜 낯설다.

그리고 `java -version` 명령으로 설치를 확인하는 부분도 단순 점검 이상으로 느껴졌다. 개발환경은 애매하게 된 것 같다고 넘어가면 나중에 더 크게 막히기 쉬우니까, 처음부터 확실히 확인하는 습관이 중요하다는 뜻으로 보였다.

## 자바 프로그램의 구조는 어떻게 생겼을까

후반부에서는 자바 프로그램의 기본 구조도 다뤘다. 아직 본격적인 객체지향 설계로 들어간 건 아니지만, 최소한 자바 코드가 어떤 재료로 이루어져 있는지는 짚고 넘어가는 느낌이었다.

### 클래스

자바 프로그램은 기본적으로 클래스 안에서 작성된다. 클래스 이름이 있고, 그 안에 변수와 메소드가 들어간다.

예제를 보면 `public class FirstJava { ... }` 같은 형태가 등장하는데, 이걸 보고 나니 자바는 "코드를 그냥 줄줄이 쓰는 언어"가 아니라 **클래스라는 틀 안에서 구조적으로 작성하는 언어**라는 점이 분명해졌다.

### 키워드, 상수, 기호, 식별자

자바 안에는 이미 정해진 키워드들이 있다. `public`, `class`, `static`, `void`, `return` 같은 단어들이 대표적이다. 이런 키워드는 약속된 기능이 있기 때문에 변수 이름이나 클래스 이름으로 마음대로 쓸 수 없다.

그리고 `true`, `false`, `null` 같은 상수, 괄호나 세미콜론 같은 기호, 클래스와 메소드와 변수에 붙는 식별자도 함께 등장한다.

처음 문법을 배울 때는 이런 요소들이 너무 잘게 쪼개져 있는 것처럼 느껴질 수 있는데, 사실은 언어를 구성하는 기본 재료를 하나씩 익히는 과정이라고 보면 된다.

### 변수

변수는 데이터를 저장하기 위한 이름 붙은 공간이다. 문자열 하나를 저장할 수도 있고, 숫자를 저장할 수도 있다. 결국 프로그램은 데이터를 입력받고 처리해서 결과를 내는 흐름으로 움직이기 때문에, 변수가 없다면 중간 상태를 기억하기 어렵다.

교안에서 상자 그림으로 설명한 게 꽤 직관적이었다. 데이터가 그냥 떠다니는 게 아니라, 이름 있는 공간에 담겨 있어야 다음 계산이나 출력에 활용할 수 있다는 뜻이다.

### 주석

주석은 프로그램이 실행하는 코드가 아니라, 사람이 읽기 위해 남기는 설명이다. 한 줄 주석과 여러 줄 주석을 구분해 소개한 부분도 나왔는데, 이건 단순 문법 이상으로 느껴졌다.

코드는 결국 혼자만 보는 게 아니고 나중의 나도 다시 보게 된다. 그래서 주석은 "컴퓨터를 위한 문장"이 아니라 "사람을 위한 문장"이라고 생각하면 이해가 더 쉽다.

### 메소드

메소드는 특정 기능을 수행하는 코드의 집합이다. 데이터를 입력받아 처리하고 결과를 돌려주는 흐름이라는 점에서, 앞서 다른 과목에서 본 `입력 -> 처리 -> 출력` 구조와도 연결된다.

교안에서도 메소드를 설명할 때 입력 데이터, 처리, 출력 결과 그림을 함께 보여줬는데, 이게 꽤 인상적이었다. 메소드 하나도 결국 작은 프로그램처럼 볼 수 있다는 뜻이기 때문이다.

그리고 `return`은 메소드를 끝내고 결과를 돌려주는 역할을 한다. 반대로 결과를 반환하지 않는 경우에는 `void`를 사용한다. 예제에서 `add` 메소드는 값을 돌려주고, `addPrint` 메소드는 화면에만 출력하는데, 이 차이를 보니 `return`과 `void`가 왜 구분되는지도 자연스럽게 이해됐다.

## 1주차를 정리하며

이번 1주차를 한 문장으로 정리하면 이렇다.

**자바 문법을 외우기 전에, 자바가 어떤 언어이고 어떤 구조로 실행되는지 먼저 잡는 시간이었다.**

객체지향의 핵심 개념인 캡슐화, 정보은닉, 추상화, 상속, 다형성을 먼저 보고, 자바가 바이트코드와 JVM을 통해 실행된다는 점을 이해하고, JDK와 개발환경을 세팅한 뒤, 클래스와 변수와 메소드 같은 기본 구조를 확인했다.

처음엔 설치 과정이 많아서 살짝 번거롭게 느껴졌지만, 지금 와서 보면 그 과정까지 포함해서 "자바를 시작하는 법" 자체를 배우는 주차였던 것 같다.
