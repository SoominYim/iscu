# [자료구조] 자료구조 학습 (1) - 자료구조와 알고리즘이란?

자료구조를 배우기 시작하면 제일 먼저 드는 생각이 있다.

그래서 이걸 왜 배워야 하지?

리스트, 스택, 큐, 트리...
이름은 많이 들어봤는데 막상 처음 보면 전부 비슷해 보이고,
그냥 파이썬 리스트 쓰면 되는 거 아닌가? 싶은 생각도 든다.

근데 조금만 들여다보면 자료구조는 단순히 자료를 저장하는 방법을 외우는 과목이 아니었다.
어떤 데이터를, 어떤 방식으로 정리하고,
필요할 때 얼마나 빠르게 꺼내 쓸 것인가를 고민하는 과목에 더 가깝다.

* * *

## 왜 자료구조를 배워야 할까?

컴퓨터는 결국 데이터를 다루는 기계다.
숫자, 문자열, 회원 정보, 게시글, 주문 내역 같은 것들을 계속 저장하고, 찾고, 수정하고, 삭제한다.

이때 데이터를 그냥 아무렇게나 넣어두면
찾을 때 오래 걸리고,
중간에 넣거나 뺄 때 비효율이 생기고,
프로그램 전체 성능에도 영향을 줄 수 있다.

쉽게 말해
방이 정리되어 있지 않으면 물건 하나 찾는데도 시간이 오래 걸리는 것처럼,
컴퓨터도 데이터를 정리하는 방식이 별로면 같은 작업을 하더라도 더 느려질 수 있다.

그래서 자료구조를 배운다는 것은
자료를 보기 좋게 정리하는 법을 배우는 것이기도 하고,
문제를 더 효율적으로 해결하는 기본기를 배우는 것이기도 하다.

* * *

## 자료구조란?

자료구조(Data Structure)는
컴퓨터에서 자료를 정리하고 조직화하는 다양한 구조를 말한다.

말 그대로 자료를 어떤 형태로 저장하고 다룰지에 대한 방식이다.

예를 들어
순서대로 줄 세워서 관리하면 리스트가 되고,
가장 마지막에 넣은 것을 먼저 꺼내면 스택이 되고,
먼저 들어온 것을 먼저 꺼내면 큐가 된다.

결국 데이터는 같아도,
어떻게 다루느냐에 따라 완전히 다른 구조가 되는 것이다.

### 자료구조의 종류

자료구조는 크게 선형 구조와 비선형 구조로 나눌 수 있다.

#### 1. 선형 자료구조

데이터가 일렬로 이어지는 구조다.

- 리스트(List)
- 스택(Stack)
- 큐(Queue)
- 덱(Deque)

순서가 중요한 구조들이라 생각하면 이해가 쉽다.

#### 2. 비선형 자료구조

데이터가 일렬이 아니라,
가지를 치거나 복잡하게 연결되는 구조다.

- 트리(Tree)
- 그래프(Graph)

회사 조직도나 폴더 구조처럼 계층이 있으면 트리,
여러 정점이 서로 자유롭게 연결되면 그래프라고 보면 된다.

* * *

## 알고리즘이란?

자료구조가 데이터를 저장하는 방식이라면,
알고리즘(Algorithm)은 문제를 해결하는 절차다.

즉,
어떤 문제를 해결하기 위해 어떤 순서로 작업을 수행할지 정해둔 규칙이라고 보면 된다.

예를 들어 사전에서 단어를 찾는다고 하면,
그냥 첫 장부터 끝까지 다 넘길 수도 있고,
가운데를 먼저 보고 범위를 반씩 줄여갈 수도 있다.

둘 다 찾기는 찾겠지만,
어떤 방법을 선택하느냐에 따라 걸리는 시간 차이가 엄청 커진다.

그래서 프로그램은 보통 이런 느낌으로 이해하면 편하다.

> 프로그램 = 자료구조 + 알고리즘

자료를 어떻게 저장할지 정하고,
그 자료를 가지고 어떤 절차로 문제를 해결할지 정하는 것.
이 두 개가 합쳐져서 결국 프로그램이 된다.

* * *

## 알고리즘이 갖춰야 할 조건

아무 절차나 적어둔다고 다 알고리즘은 아니다.
알고리즘이라면 최소한 아래 조건은 만족해야 한다.

### 1. 입력(input)

0개 이상의 입력이 있어야 한다.
물론 입력이 아예 없는 경우도 있을 수 있다.

### 2. 출력(output)

최소 1개 이상의 결과가 나와야 한다.
아무 결과도 내지 못하면 문제 해결 절차라고 보기 어렵다.

### 3. 명확성(definiteness)

각 단계의 의미가 모호하면 안 된다.
누가 봐도 같은 방식으로 이해할 수 있어야 한다.

### 4. 유한성(finiteness)

언젠가는 반드시 끝나야 한다.
계속 돌기만 하고 종료되지 않으면 알고리즘이라고 보기 어렵다.

### 5. 유효성(effectiveness)

각 단계가 실제로 수행 가능한 연산이어야 한다.
말만 그럴듯하고 실행할 수 없는 작업이면 안 된다.

이 다섯 가지를 보면 결국 핵심은 하나다.

**입력이 들어왔을 때, 명확하고 실행 가능한 절차로, 언젠가 끝나며, 결과를 내야 한다.**

* * *

## 추상자료형(ADT)은 또 뭘까?

처음 들으면 이름부터 좀 무섭다.
추상자료형(Abstract Data Type)...
괜히 어려워 보인다.

근데 생각보다 개념은 단순하다.

추상자료형은
**데이터가 무엇이고, 어떤 연산을 제공하는지만 정의하고,
그 내부가 어떻게 구현되어 있는지는 감추는 방식**이다.

즉,
사용자는 "어떻게 만들어졌는지" 보다
"무엇을 할 수 있는지"에 집중하면 된다.

### Bag 예시로 이해하기

교안에서는 가방(Bag)을 예시로 든다.

가방을 생각해보면
물건이 들어 있고,
물건을 넣을 수 있고,
뺄 수 있고,
특정 물건이 있는지 확인할 수 있고,
전체 개수도 셀 수 있다.

이걸 ADT 관점으로 보면 대충 이렇게 된다.

#### 데이터

- 중복된 항목을 허용할 수 있음
- 특별한 순서 없이 개별적으로 저장됨
- 항목 간 비교는 가능함

#### 연산

- `insert(e)` : 항목 넣기
- `remove(e)` : 항목 삭제하기
- `contains(e)` : 항목 존재 여부 확인
- `count()` : 전체 개수 반환

중요한 건
이 가방이 실제로는 파이썬 리스트로 구현되든,
집합처럼 구현되든,
다른 방식으로 구현되든,
사용자는 저 연산만 잘 쓰면 된다는 점이다.

이게 ADT의 핵심이다.

### 파이썬으로 아주 간단히 표현하면

```python

def contains(bag, e):
    return e in bag


def insert(bag, e):
    bag.append(e)


def remove(bag, e):
    bag.remove(e)


def count(bag):
    return len(bag)
```

이 코드는 구현체의 한 예시일 뿐이고,
우리가 정말 봐야 하는 건
"가방은 이런 연산을 제공하는구나" 라는 점이다.

## 알고리즘 성능 분석

이제 문제는 하나 남는다.

그래서 어떤 알고리즘이 더 좋은데?

이걸 판단하기 위해 성능 분석을 한다.
교안에서는 크게 두 가지로 나눈다.

### 1. 실행시간 측정

실제로 코드를 돌려서 시간을 재는 방법이다.

이 방법은 직관적이긴 한데,
컴퓨터 성능, 실행 환경, 입력 데이터에 따라 결과가 달라질 수 있다.

즉,
내 컴퓨터에서 빠르다고 해서
항상 더 좋은 알고리즘이라고 단정할 수는 없다.

### 2. 복잡도 분석

직접 실행하지 않고,
알고리즘이 수행하는 연산 횟수를 계산하는 방법이다.

보통은
- 산술 연산
- 대입 연산
- 비교 연산
- 이동 연산

같은 기본 연산이 얼마나 수행되는지를 본다.

이론적으로 비교할 수 있어서,
알고리즘을 평가할 때 훨씬 많이 쓰인다.

* * *

## 시간 복잡도와 공간 복잡도

### 시간 복잡도(Time Complexity)

입력 크기가 커질수록
실행 시간이 어떻게 늘어나는지를 보는 개념이다.

정확히는 시간을 직접 재는 것보다는,
연산 횟수가 얼마나 증가하는지를 보는 것에 가깝다.

### 공간 복잡도(Space Complexity)

알고리즘이 실행되는 동안
추가로 얼마나 많은 메모리를 사용하는지를 보는 개념이다.

보통은 시간 복잡도를 더 자주 보지만,
메모리 사용량이 중요한 상황에서는 공간 복잡도도 매우 중요하다.

* * *

## 빅오 표기법

시간 복잡도를 이야기할 때 제일 많이 보는 것이 빅오 표기법이다.

빅오 표기법은
입력 크기 `n`이 커질 때,
알고리즘의 증가 속도를 대략적으로 표현한 방법이다.

### 왜 대략적으로 표현할까?

입력이 커질수록
영향이 큰 항만 남기고,
작은 항이나 상수는 무시해도 전체 흐름을 이해하는 데 문제가 없기 때문이다.

예를 들어

```text
T(n) = n² + n + 1
```

이 식이 있다고 해보자.

`n`이 작을 때는 `+n`, `+1`도 좀 보이지만,
`n`이 커질수록 사실상 `n²`이 거의 다 먹는다.

그래서 이 식은

```text
O(n²)
```

라고 표현한다.

즉,
빅오를 볼 때는

- 상수는 무시하고
- 낮은 차수 항은 무시하고
- 가장 크게 증가하는 항만 본다

이렇게 이해하면 된다.

### 자주 보는 빅오 종류

- `O(1)` : 상수형
- `O(log n)` : 로그형
- `O(n)` : 선형
- `O(n log n)` : 선형로그형
- `O(n²)` : 2차형
- `O(n³)` : 3차형
- `O(2^n)` : 지수형
- `O(n!)` : 팩토리얼형

보통 아래로 갈수록 훨씬 느려진다.

그래서 입력이 커질 가능성이 있다면
`O(n²)` 이상은 꽤 부담스럽게 느껴질 수 있다.

* * *

## 최선, 평균, 최악의 경우

같은 알고리즘이라도
입력 데이터 상태에 따라 속도가 달라질 수 있다.

예를 들어 이미 정렬된 데이터에선 빠르게 끝날 수도 있고,
완전히 뒤죽박죽이면 오래 걸릴 수도 있다.

그래서 보통 세 가지 경우로 나눠서 본다.

- 최선의 경우(best case)
- 평균의 경우(avg case)
- 최악의 경우(worst case)

실제로는 평균을 정확히 구하기가 까다로운 경우가 많아서,
보통은 **최악의 경우**를 많이 사용한다.

최악의 상황에서도 이 정도 성능은 보장된다는 의미가 되기 때문이다.

## 순환 알고리즘(재귀)은 왜 배우는 걸까?

순환 알고리즘은
함수 안에서 자기 자신을 다시 호출하는 방식이다.

처음 보면 좀 이상하다.

아니 함수가 자기 자신을 또 부르면
도대체 언제 끝나지?

그래서 순환 알고리즘을 작성할 때는 반드시 두 가지가 필요하다.

### 1. 종료 조건

언제 멈출지 정해둬야 한다.

### 2. 더 작은 문제로 줄이는 과정

원래 문제를 조금 더 작은 같은 형태의 문제로 바꿔야 한다.

즉,
계속 같은 크기의 문제를 던지면 안 되고,
반드시 끝에 도달할 수 있게 문제 크기가 줄어들어야 한다.

* * *

## 순환 알고리즘 예시 1. 팩토리얼

팩토리얼은 순환을 설명할 때 거의 단골 예시다.

```python

def factorial(n):
    if n == 1:
        return 1
    return n * factorial(n - 1)
```

이 코드는

- `n == 1`이면 끝내고
- 아니면 `n * factorial(n-1)`을 계산한다.

예를 들어 `factorial(3)`은

```text
3 * factorial(2)
3 * 2 * factorial(1)
3 * 2 * 1
= 6
```

이런 식으로 계산된다.

문제 자체가
`n! = n * (n-1)!`
형태로 정의되어 있으니,
순환으로 표현하기가 굉장히 자연스럽다.

### 그럼 반복문이 더 좋은 거 아닌가?

사실 대부분의 순환은 반복으로 바꿔서 작성할 수 있다.

그리고 보통 반복문이
함수 호출 오버헤드가 없어서 더 빠른 경우가 많다.

즉,
순환은 **문제를 표현하기는 자연스럽지만**,
항상 더 빠른 것은 아니다.

* * *

## 순환 알고리즘 예시 2. 거듭제곱

거듭제곱도 재미있는 예시다.

단순하게 `x`를 `n`번 곱하면 `O(n)`이지만,
문제를 절반씩 줄이면 훨씬 빨라질 수 있다.

```python

def power(x, n):
    if n == 0:
        return 1
    elif n % 2 == 0:
        return power(x * x, n // 2)
    else:
        return x * power(x * x, (n - 1) // 2)
```

이 방식은 한 번 호출할 때마다 문제 크기가 절반 가까이 줄어든다.
그래서 시간 복잡도는 `O(log n)`이 된다.

이걸 보면 순환이 무조건 비효율적인 건 아니라는 걸 알 수 있다.
문제를 어떻게 줄이느냐가 핵심이다.

* * *

## 순환 알고리즘 예시 3. 피보나치 수열

피보나치는 순환의 장단점을 동시에 보여주는 대표 예시다.

```python

def fib(n):
    if n == 0:
        return 0
    elif n == 1:
        return 1
    else:
        return fib(n - 1) + fib(n - 2)
```

겉보기엔 너무 깔끔하다.
근데 이 코드는 같은 값을 계속 중복 계산한다.

예를 들어 `fib(5)`를 구할 때
`fib(3)`, `fib(2)` 같은 값이 여러 번 반복 호출된다.

그래서 시간 복잡도가 `O(2^n)` 수준까지 커진다.

반면 반복문으로 작성하면
이전 두 값만 기억하면서 차례대로 계산할 수 있어서 `O(n)`으로 줄어든다.

즉,
순환이 보기에는 예뻐도,
성능은 별로일 수 있다.

여기서 중요한 건
**코드가 짧고 깔끔한 것과 효율적인 것은 별개**라는 점이다.

## 순환 알고리즘 예시 4. 하노이 탑

하노이 탑은 순환의 감을 잡기 좋은 문제다.

원판 `n-1`개를 보조 기둥으로 옮기고,
가장 큰 원판 하나를 목적지로 옮기고,
다시 `n-1`개를 목적지로 옮긴다.

이 구조가 그대로 자기 자신을 호출하는 형태가 된다.

```python

def hanoi_tower(n, fr, tmp, to):
    if n == 1:
        print(f"원판 1: {fr} --> {to}")
    else:
        hanoi_tower(n - 1, fr, to, tmp)
        print(f"원판 {n}: {fr} --> {to}")
        hanoi_tower(n - 1, tmp, fr, to)
```

하노이 탑의 시간 복잡도는 `O(2^n)`이다.
원판 개수가 조금만 늘어도 경우의 수가 확 늘어난다.

그래서 순환이 잘 어울리는 문제이긴 하지만,
입력이 커지면 금방 무거워진다.

## 여기까지 배우고 느낀 점

처음에는 자료구조가
리스트 외우기,
스택 외우기,
큐 외우기 같은 과목인 줄 알았다.

근데 첫 단원부터 느낀 건
이 과목은 결국 **어떻게 저장할 것인가**, **어떻게 처리할 것인가**, **얼마나 효율적인가**를 계속 묻는 과목이라는 점이다.

- 자료구조는 데이터를 정리하는 방식이고
- 알고리즘은 문제를 해결하는 절차이고
- ADT는 구현보다 기능에 집중하는 개념이고
- 시간 복잡도는 그 절차가 얼마나 효율적인지 보는 기준이고
- 순환 알고리즘은 문제를 더 작은 같은 문제로 나누어 해결하는 방식이다.

이 기본기가 뒤에서 계속 등장할 것 같다.
스택, 큐, 트리, 그래프를 배우더라도 결국 이 위에 올라가는 느낌이다.

일단 지금은
`O(n)`이랑 `O(n²)`를 봤을 때 덜 무서워지고,
순환 함수를 봤을 때 "아 얘는 종료 조건이 뭐지?"를 먼저 생각할 수 있는 상태가 되는 게 목표다.

다음엔 본격적으로 리스트, 스택, 큐 쪽으로 넘어가야겠다.
그때부터가 진짜 자료구조 시작일 것 같다.
