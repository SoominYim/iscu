# [컴퓨터개론] 컴퓨터개론 학습 (7) - `프로그래밍 언어`와 `웹 시스템` 핵심 정리

코드를 배울 때는 자꾸 문법만 먼저 보게 된다. `if`, `while`, 함수, 클래스 같은 것들 말이다. 그런데 막상 프로그램이 실행되는 전체 구조를 떠올리라고 하면 생각보다 흐릿할 때가 많다.

이번 7주차 `컴퓨터개론` 교안은 그 흐릿한 부분을 꽤 넓게 훑는다. 앞쪽에서는 `프로그래밍 언어`의 종류와 `컴파일러`와 `인터프리터`, `버그`, `디버깅`, `테스팅`, 주요 언어 특성을 정리하고, 뒤쪽에서는 `웹 시스템`, `클라이언트/서버`, `데몬`, `HTML`, `CGI`, `XML`, `메타데이터`, `HTML5`, `HTML/CSS/JavaScript`까지 이어진다.

한 주차 안에 다루는 범위가 제법 넓어서 처음에는 조금 산만해 보일 수도 있다. 그런데 끝까지 보고 나면 오히려 하나의 흐름이 보인다. 코드가 어떤 언어로 쓰이고, 어떻게 실행되고, 웹에서는 어떤 구조 위에서 동작하는지를 한 번에 이어 주는 흐름 말이다.

## `저급 언어`와 `고급 언어` 구분 기준

교안 초반은 `기계어`, `어셈블리어`, `고급 언어`를 구분하는 데서 시작한다.

### 컴퓨터 중심 언어와 사람 중심 언어의 차이

`기계어`는 숫자 형태의 언어이고, `어셈블리어`는 그걸 사람이 조금 더 읽을 수 있게 바꾼 저급 언어다. 반면 `if (num > 3)` 같은 형태는 사람이 이해하기 쉬운 고급 언어 쪽에 속한다.

이 구분은 너무 기본처럼 보여도 꽤 중요했다. 프로그래밍 언어가 왜 계속 추상화 방향으로 발전해 왔는지 이해하게 해 주기 때문이다.

### 프로그래밍 언어의 역할과 거리 조절

컴퓨터는 기계어만 이해하지만 사람은 그걸 직접 다루기 어렵다. 그래서 중간에 더 읽기 쉬운 언어가 생기고, 또 더 큰 문제를 다루기 쉽게 고급 언어가 발전해 온 것이다.

이번 주차를 보며 언어 종류를 외우는 것보다, "누구에게 더 가까운 언어인가"라는 질문으로 정리하는 편이 훨씬 선명하게 남았다.

## `객체지향 언어`와 코드 구조 정리

교안은 `객체지향 언어`를 변수와 함수, 즉 메소드가 하나로 묶여 데이터를 처리하는 방식으로 설명한다.

### 데이터와 행동을 함께 보는 코드 구조

데이터만 따로 두고 처리 코드를 여기저기 흩어 놓는 것보다, 관련 있는 변수와 메소드를 객체 단위로 묶는 편이 훨씬 이해하기 쉽다. 그래서 객체지향은 단순한 문법 범주가 아니라 프로그램을 조직하는 방식처럼 느껴진다.

이번 주차에서 이 부분이 반가웠던 건, 앞선 다른 과목에서 보던 클래스나 객체 개념이 컴퓨터개론 차원에서 다시 넓게 설명된다는 점이었다. 덕분에 객체지향이 언어 기능을 넘어 사고 방식이라는 점이 더 잘 들어왔다.

### `소스 코드`의 의미와 설계 기록

교안은 소스 코드를 프로그래밍 언어로 작성한 결과물로 보여 준다. 이 표현도 꽤 좋았다. 실행 파일이 아니라, 사람이 읽고 수정하고 검토할 수 있는 원본이라는 느낌이 강하기 때문이다.

그래서 프로그래밍은 단순히 돌아가는 결과를 만드는 일이 아니라, 읽고 고치고 설명할 수 있는 형태를 남기는 일이기도 하다는 생각이 들었다.

## `컴파일러`와 `인터프리터` 실행 방식 비교

7주차 중반에서는 `컴파일러 언어`와 `인터프리터 언어`가 비교된다.

### `컴파일` 방식의 구조

고급 언어로 쓴 소스 코드를 기계어로 변환해 실행 파일을 만든 뒤 실행하는 방식이다. 교안에서도 컴파일러는 실행 전 오류를 확인하고, 실행 파일을 만들어 한꺼번에 실행한다고 정리한다.

이 방식은 준비 단계가 분명한 대신, 실행 시에는 비교적 빠르고 반복 실행에 유리하다는 감각이 생긴다.

### `인터프리터` 방식의 흐름

반면 인터프리터는 소스 코드를 한 번에 한 줄씩 번역하며 실행한다. 실행 전에 완성된 실행 파일을 만드는 흐름과는 다르다.

두 방식을 비교해 보니, 컴파일러와 인터프리터는 단순히 언어 종류를 나누는 말이 아니라 프로그램이 "언제 번역되고 언제 실행되는가"를 구분하는 말이라는 점이 분명해졌다.

## `프로그래밍 과정` 전체 흐름

교안은 `요구 분석`, `알고리즘 작성`, `코드 작성`, `컴파일`, `실행` 같은 흐름을 보여 준다.

### 코딩의 위치와 문제 해결 과정

이 순서를 보면 코드 작성은 전체 과정의 중간에 있다. 앞에는 요구 분석과 알고리즘 정리가 있고, 뒤에는 컴파일과 실행, 그리고 확인이 있다.

이 구조를 보면 왜 초반에 문제를 잘못 이해하면 뒤에서 아무리 코드를 고쳐도 힘든지 자연스럽게 납득된다.

### `버그`, `디버깅`, `테스팅`, `최적화`의 역할

`버그`는 코드에서 발생하는 오류이고, `디버깅`은 그 오류를 찾아 수정하는 과정이다. 여기에 `구문 오류`, `실행 시간 오류`, `논리 오류`까지 나뉜다.

이 분류가 좋았던 이유는 오류를 막연하게 보지 않게 해 주기 때문이다. 문법이 틀린 건지, 실행하다 터지는 건지, 실행은 되지만 결과가 틀린 건지에 따라 접근 방식이 달라진다.

`테스팅`과 `코드 최적화`가 뒤에 이어지는 것도 자연스럽다. 돌아가는 것과 잘 돌아가는 것은 다르기 때문이다.

## `주요 프로그래밍 언어` 비교 포인트

교안은 `C`, `Java`, `Python` 같은 대표 언어를 예로 든다.

### `C` 언어의 특징

간결한 문법 구조, 기계에 가까운 제어, 빠른 실행 속도 같은 장점이 정리된다. 그래서 시스템 프로그래밍이나 임베디드처럼 성능과 제어가 중요한 환경에서 자주 언급되는 이유가 이해됐다.

### `Java`와 `JVM` 구조

교안의 `가상머신(Java Virtual Machine)` 설명은 꽤 중요했다. 운영체제가 달라도 같은 환경처럼 실행되게 만든다는 점이 `Java`의 장점을 분명히 보여 주기 때문이다.

언어 자체만 보는 게 아니라, 실행 환경을 함께 설계한다는 점에서 `Java`는 다른 결의 장점을 가진다.

### `Python`의 강점과 활용 범위

문법이 비교적 간단하고, `머신러닝`이나 여러 응용 분야에서도 폭넓게 활용된다는 설명이 나온다. 이 흐름을 보며 언어 선택은 무조건 성능만이 아니라, 생산성과 적용 분야도 함께 봐야 한다는 생각이 들었다.

## `웹 시스템` 기본 구조

이번 주차 후반은 `웹 프로그래밍`, `클라이언트/서버`, `데몬`, `마크업 언어`, `CGI`, `XML`, `메타데이터`, `HTML5`, `HTML 태그`까지 이어진다.

### `클라이언트`와 `서버` 역할 구분

서비스를 요청하는 쪽이 `클라이언트`, 서비스를 제공하는 쪽이 `서버`라는 기본 구분은 단순하지만 아주 중요하다. 여기에 HTTP 처리 역할을 하는 `HTTPD` 같은 데몬 개념이 붙으면서 웹 시스템의 기본 흐름이 보인다.

웹은 결국 브라우저에서 보이는 화면만의 문제가 아니라, 요청과 응답이 오가는 구조 전체라는 점이 여기서 다시 분명해진다.

### `마크업 언어`의 의미와 구조

교안은 `SGML`, `HTML`, `XML`을 연결해 설명한다. 특히 `HTML`은 웹 페이지 내용을 표현하는 언어이고, `XML`은 사용자 정의 태그를 사용할 수 있는 마크업 언어로 나온다.

이 부분이 좋았던 이유는, 태그가 단순히 화면 장식이 아니라 데이터의 의미와 속성을 표현하는 수단이라는 점을 보여 주기 때문이다. `메타데이터` 개념도 같은 맥락으로 이어진다.

### `CGI`, `HTML`, `CSS`, `JavaScript` 연결 구조

교안은 `CGI`를 운영체제나 응용프로그램의 응답을 HTML에 맞게 변형하는 인터페이스로 설명하고, 웹페이지 구성 3요소로 `HTML`, `CSS`, `JavaScript`를 다시 정리한다.

특히 이 부분은 프론트엔드 관점과도 은근히 맞닿아 있었다. 웹페이지에서 보이는 구조는 `HTML`, 외관은 `CSS`, 동적인 행동은 `JavaScript`가 맡는다는 기본 분리가 다시 한번 선명하게 느껴졌기 때문이다.

## `HTML`, `CSS`, `JavaScript` 역할 분담

웹을 처음 배우면 화면에 보이는 모든 것을 그냥 "웹페이지"라고 한 덩어리로 받아들이기 쉽다. 그런데 교안처럼 웹페이지 구성 3요소를 분리해서 보면 각 요소가 맡는 역할이 꽤 명확하다.

### 구조, 표현, 동작의 분리

`HTML`은 본문과 제목, 줄바꿈, 태그 구조처럼 문서의 뼈대를 만든다. `CSS`는 그 뼈대가 어떻게 보일지를 정하고, `JavaScript`는 버튼 클릭이나 동적인 변화처럼 움직이는 부분을 담당한다.

이 구분이 중요한 이유는, 웹을 만드는 일이 단순히 화면을 그리는 일이 아니라 구조, 표현, 행동을 나눠 설계하는 일이라는 점을 보여 주기 때문이다. 실제로 프론트엔드 작업에서도 이 분리가 흐려지면 수정이 금방 어려워진다.

### 기본 태그 학습의 중요성

교안 후반의 `HTML` 태그 예시, `<HTML>`, `<HEAD>`, `<TITLE>`, `<BODY>`, `<BR>` 같은 요소들은 아주 기초처럼 보인다. 그런데 이 기초가 있어야 브라우저가 문서를 어떻게 해석하는지도 이해된다.

결국 태그는 외워야 하는 기호라기보다, 문서 안에서 어떤 부분이 어떤 역할을 하는지를 표시하는 약속이었다. 그 약속이 분명해야 웹페이지 전체 구조도 읽힌다.

## `메타데이터`와 `반정형 데이터` 이해

7주차 후반부에서 `메타데이터`와 `반정형 데이터`, `XML`이 함께 나오는 흐름도 좋았다.

### 데이터 `의미`와 `속성`의 분리

교안은 메타데이터를 데이터의 의미나 속성을 규정하는 데이터라고 설명한다. 이 표현은 짧지만 중요하다. 같은 값이라도 그것이 이름인지, 전화번호인지, 직장 정보인지 모르면 데이터는 제대로 쓰이기 어렵기 때문이다.

이런 시선으로 보면 웹은 단순히 예쁜 화면을 만드는 기술이 아니다. 정보를 구조화하고, 의미를 붙이고, 다른 시스템이 이해할 수 있게 전달하는 기술이라는 점이 더 크게 보인다.

### `XML`과 반정형 데이터의 필요성

정형 데이터처럼 딱딱한 표만으로는 담기 어려운 정보를, 구조와 태그를 함께 이용해 표현할 수 있다는 점에서 `XML`은 꽤 인상적이었다. 사용자 정의 태그를 활용해 의미를 드러낼 수 있다는 점도 마찬가지다.

그래서 이번 주차의 웹 시스템 파트는 브라우저 화면 이야기만이 아니라, 데이터가 웹에서 어떤 구조로 표현되고 교환되는지까지 한 번에 훑는 시간처럼 느껴졌다.

## 7주차 핵심 정리

이번 주차는 `프로그래밍 언어`, `객체지향`, `컴파일러`, `인터프리터`, `버그`, `디버깅`, `테스팅`, `가상머신`, `웹 시스템`, `HTML`, `CGI`, `XML`, `메타데이터`까지 이어지며 범위가 넓었다.

그런데 오히려 그래서 좋았다. 코드는 파일 안에만 있는 게 아니라 번역되고, 실행되고, 오류를 거치고, 웹 시스템 안에서 요청과 응답을 만들며 살아 움직인다는 걸 한 번에 보여 줬기 때문이다.

## 중간고사 정리 포인트

중간고사 범위가 여기까지라면 7주차 `컴퓨터개론`은 사실상 정리의 성격도 꽤 강하다. `저급/고급 언어`, `객체지향`, `컴파일/인터프리터`, `버그와 디버깅`, `클라이언트/서버`, `HTML/CSS/JavaScript`, `메타데이터`처럼 앞뒤 개념이 한 번에 모여 있기 때문이다.

시험 준비를 할 때는 각각을 따로 외우기보다 "코드가 어떻게 쓰이고, 어떻게 실행되고, 웹에서는 어떻게 전달되는가"라는 흐름으로 묶어 두는 게 좋겠다고 느꼈다. 특히 `컴파일러 vs 인터프리터`, `오류 종류`, `JVM`, `웹페이지 구성 3요소`는 꼭 한 번 더 정리해 둘 만한 포인트였다.
