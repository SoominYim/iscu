# [자료구조] 자료구조 학습 (7) - 기본 `정렬` 알고리즘과 처리 방식 정리

정렬은 처음 보면 꽤 단순해 보인다. 숫자를 오름차순으로 놓거나 이름순으로 다시 배열하는 일처럼 보이기 때문이다. 그런데 막상 어떤 방식으로 정렬할지를 들여다보기 시작하면 얘기가 달라진다.

같은 결과를 만들더라도 데이터를 얼마나 많이 비교하는지, 얼마나 많이 움직이는지, 이미 어느 정도 정렬된 상태에서 유리한지, 원래 순서를 유지하는지에 따라 알고리즘의 성격이 전혀 달라진다.

이번 7주차 `자료구조` 교안은 바로 그 차이를 꽤 또렷하게 보여 준다. `정렬의 개념과 특징`, 정렬의 여러 분류 기준, 그리고 `선택 정렬`, `삽입 정렬`, `버블 정렬` 같은 기본 정렬 알고리즘이 차례대로 이어진다.

이번 주차를 보고 나니 정렬은 "순서를 맞춘다"는 한 줄 설명으로는 부족했다. 오히려 같은 정렬이라도 어떤 비용을 감수하고 어떤 상황에서 더 잘 동작하는지를 비교하는 시간이 더 본질에 가까웠다.

## `정렬`의 개념과 기준

교안은 정렬을 데이터나 레코드를 어떤 기준에 따라 다시 배열하는 작업으로 설명한다. 오름차순, 내림차순 같은 말도 여기서 자연스럽게 연결된다.

### 정렬 기준과 순서 결정

숫자라면 크기 순으로, 이름이라면 가나다순으로, 점수라면 높은 순으로 정렬할 수 있다. 교안이 경주마 예시나 생활 속 정렬 예시를 보여 주는 이유도 여기 있는 것 같았다.

정렬은 알고리즘이기 전에 기준을 세우는 일이다. 무엇을 비교할지 정하지 않으면, 어떤 순서가 맞는지 자체가 성립하지 않는다.

### `키(key)`와 `레코드(record)` 개념

7주차에서 `레코드` 개념이 다시 등장하는 것도 좋았다. 하나의 레코드 안에는 여러 속성이 있지만, 정렬은 보통 그중 특정 `키` 값을 기준으로 이뤄진다.

이걸 이해하고 나면 정렬은 단순히 숫자 배열만 다루는 단원이 아니라, 실제 데이터를 어떤 속성 기준으로 재배열하는 문제라는 점이 더 잘 보인다.

## `정렬의 분류` 기준

교안은 정렬을 여러 기준으로 나눈다. `효율성`, `정렬 장소`, `키값 비교 여부`, 그리고 `안정성`이나 `제자리 정렬` 여부 같은 특징까지 함께 다룬다.

### 단순 정렬과 고효율 정렬 차이

`삽입 정렬`, `선택 정렬`, `버블 정렬`은 단순하지만 비교적 비효율적인 정렬로 분류되고, `퀵 정렬`, `병합 정렬`, `셸 정렬`은 더 복잡하지만 효율적인 정렬로 묶인다.

이 구분이 좋았던 이유는, 알고리즘이 단순하다고 좋은 것도 아니고 복잡하다고 무조건 어려운 것도 아니라는 점을 보여 주기 때문이다. 무엇을 얻고 무엇을 포기하는지가 더 중요하다.

### `내부 정렬`과 `외부 정렬` 차이

모든 데이터를 주기억장치에 올려 놓고 정렬할 수 있으면 `내부 정렬`이 되고, 그게 불가능해서 일부만 메모리에 두고 나머지는 외부기억장치에 둔 채 정렬하면 `외부 정렬`이 된다.

이 구분은 정렬이 교실 속 예제만이 아니라 실제 데이터 규모와도 연결된다는 점을 보여 준다. 데이터가 많아질수록 알고리즘은 메모리 환경까지 같이 고려해야 한다는 뜻이다.

### `안정성`과 `제자리 정렬` 중요성

교안은 정렬 후에도 같은 키를 가진 레코드들의 원래 순서가 유지되면 `안정성`을 만족한다고 설명한다. 이 기준은 단순해 보여도 실제 데이터 처리에서는 꽤 중요하다.

또 `제자리 정렬` 여부는 추가 메모리 사용과도 이어진다. 결국 정렬 알고리즘은 속도만 보는 게 아니라, 순서 보존과 공간 사용까지 같이 보는 문제라는 뜻이다.

## `선택 정렬` 핵심 구조

교안의 첫 번째 기본 정렬은 `선택 정렬`이다.

### 최솟값 선택 방식

오른쪽 리스트에서 최솟값을 고른 뒤, 왼쪽 정렬된 리스트의 맨 뒤로 옮기는 작업을 반복한다는 설명은 정말 직관적이다. 매 단계마다 정렬된 영역은 커지고, 정렬되지 않은 영역은 줄어든다.

이 단순함 덕분에 선택 정렬은 정렬 알고리즘을 처음 이해할 때 꽤 좋은 출발점처럼 느껴졌다.

### 반복 탐색과 속도 한계

정렬되지 않은 부분의 최솟값을 찾으려면 계속 끝까지 훑어야 한다. 그래서 구현은 단순하지만 효율성은 좋지 않다.

교안도 선택 정렬의 특징으로 `속도가 느림`, `안정성을 만족하지 않음`, `알고리즘이 간단함`, `제자리 정렬`, `자료 이동 횟수가 미리 결정됨`을 함께 적고 있다. 장점과 단점이 꽤 분명한 알고리즘인 셈이다.

#### `선택 정렬` 코드 구조

```python
def selection_sort(arr):
    arr = arr[:]
    n = len(arr)

    for i in range(n - 1):
        min_index = i

        for j in range(i + 1, n):
            if arr[j] < arr[min_index]:
                min_index = j

        arr[i], arr[min_index] = arr[min_index], arr[i]

    return arr
```

이 코드를 보면 선택 정렬은 매 바깥 반복마다 `가장 작은 값의 위치`를 처음부터 다시 찾는다. 그래서 이동 횟수는 비교적 예측 가능하지만, 비교 자체는 꾸준히 많이 일어난다. 교안에서 말한 "단순하지만 느리다"는 평가가 추상적인 말이 아니라 코드 흐름에서 바로 읽힌다.

## `삽입 정렬` 핵심 구조

선택 정렬이 "최솟값을 찾아 앞으로 보내는 정렬"이라면, `삽입 정렬`은 "새 값을 정렬된 영역 안에 끼워 넣는 정렬"에 더 가깝다.

### 카드 삽입 방식의 이미지

교안이 삽입 정렬을 설명할 때 새로 받은 카드를 자기 위치에 넣는 느낌으로 보여 주는 부분이 꽤 좋았다. 이미 정렬된 왼쪽 부분이 있고, 오른쪽 첫 항목을 적절한 위치로 넣는 방식이기 때문이다.

이 비유 덕분에 삽입 정렬은 정렬 알고리즘 중에서도 특히 동작 그림이 잘 그려졌다.

### 입력 상태와 성능 차이

이미 어느 정도 정렬돼 있다면 삽입 정렬은 꽤 효율적으로 움직인다. 들어갈 위치가 맨 끝에 가까우면 이동이 거의 없기 때문이다.

반대로 역순으로 정렬된 경우에는 매번 앞의 자료들을 많이 밀어야 해서 비효율적이다. 교안이 이 점을 따로 강조하는 이유도 이해가 갔다. 삽입 정렬은 입력 데이터 상태의 영향을 많이 받는 알고리즘이다.

### `대부분 정렬된 데이터`에서의 강점

이번 주차를 보며 삽입 정렬은 단순 정렬 알고리즘이면서도 상황 적응성이 있다는 점이 흥미로웠다. 정렬 알고리즘의 효율이 입력 상태에 따라 달라질 수 있다는 사실을 가장 실감 나게 보여 주는 예시 같았다.

#### `삽입 정렬` 코드 구조

```python
def insertion_sort(arr):
    arr = arr[:]

    for i in range(1, len(arr)):
        current = arr[i]
        j = i - 1

        while j >= 0 and arr[j] > current:
            arr[j + 1] = arr[j]
            j -= 1

        arr[j + 1] = current

    return arr
```

여기서는 `current`를 임시로 들고 뒤에서부터 밀어내는 과정이 핵심이다. 이미 왼쪽이 어느 정도 정렬되어 있으면 `while` 문이 길게 돌지 않기 때문에 훨씬 빨리 끝난다. 그래서 삽입 정렬은 코드 한 줄 한 줄이 교안의 설명과 정확히 연결되는 편이었다.

## `버블 정렬` 핵심 구조

세 번째 기본 정렬은 `버블 정렬`이다.

### 인접 비교와 교환 방식

맨 앞부터 한 칸씩 이동하면서 두 원소가 순서대로 되어 있지 않으면 자리를 바꾸는 방식이다. 그리고 한 번의 스캔이 끝나면 가장 큰 값이 오른쪽 끝으로 올라간다.

동작 모습이 눈에 잘 보여서 원리는 이해하기 쉽다. 정렬이 실제로 어떻게 진행되는지 시각적으로 보여 주는 데는 꽤 좋은 알고리즘이다.

### 비교 횟수와 이동 비용

교안도 `최악 혹은 평균적인 경우 시간복잡도가 O(n²)`라고 정리한다. 특히 이동 횟수가 많다는 점이 부담이다.

다만 이미 정렬되어 있는 경우처럼 어느 정도 정돈된 입력에서는 교환이 빨리 줄어들 수 있다. 그래서 버블 정렬도 입력 상태를 어느 정도 타는 알고리즘으로 볼 수 있다.

#### `버블 정렬` 코드 구조

```python
def bubble_sort(arr):
    arr = arr[:]
    n = len(arr)

    for i in range(n - 1):
        swapped = False

        for j in range(n - 1 - i):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
                swapped = True

        if not swapped:
            break

    return arr
```

인접한 두 값을 계속 비교하고 자리를 바꾸는 구조라서, 동작은 눈에 잘 보이지만 교환 횟수도 쉽게 늘어난다. 대신 `swapped` 같은 플래그를 두면 이미 정렬된 상태에서는 조기에 끝낼 수 있다는 점도 같이 확인할 수 있다. 그래서 버블 정렬은 단순한 만큼 개선 포인트도 코드에서 금방 읽힌다.

## 세 정렬 알고리즘 비교 포인트

선택 정렬, 삽입 정렬, 버블 정렬은 모두 기본 정렬로 묶이지만 실제 느낌은 꽤 다르다. 이번 주차가 좋았던 이유도 바로 이 차이를 한 장면씩 체감하게 해 준다는 점이었다.

### `선택 정렬`과 `삽입 정렬` 차이

선택 정렬은 매번 최소값을 찾아 앞쪽으로 보내기 때문에 흐름은 단순하다. 대신 같은 키를 가진 레코드의 상대적 순서를 자연스럽게 보존하지 못할 수 있어 안정성이 약하다.

반면 삽입 정렬은 이미 어느 정도 정렬된 상태일수록 유리하다. 새 항목이 거의 제자리에 있으면 비교와 이동이 적어지기 때문이다. 그래서 삽입 정렬은 단순한 알고리즘이면서도 실제 데이터 상태의 영향을 꽤 민감하게 받는다.

### `버블 정렬` 특징과 한계

버블 정렬은 인접 원소를 비교하고 바꾸는 모습이 눈에 잘 보이기 때문에, 정렬의 동작 원리를 시각적으로 이해하는 데는 아주 좋다. 하지만 그만큼 교환이 자주 일어나 이동 비용이 커진다.

결국 셋 모두 `O(n²)` 계열의 기본 정렬이지만, 무엇을 많이 하는지와 어떤 상황에서 덜 손해를 보는지가 다르다. 이 차이를 알고 나면 정렬을 그냥 같은 급의 느린 알고리즘 세 개로 묶어 보지 않게 된다.

## 정렬 알고리즘 비교 기준

선택 정렬은 단순하고 이동 횟수가 예측 가능하지만 느리고 안정적이지 않다. 삽입 정렬은 대부분 정렬된 상황에 강하고 안정적이지만, 역순 입력에서는 부담이 커진다. 버블 정렬은 동작이 직관적이지만 교환이 많아 평균적으로 느리다.

### 성능표보다 중요한 사고방식

정렬이란 무엇인지, 레코드와 키를 어떻게 보는지, 어떤 방식으로 정렬된 영역과 미정렬 영역을 다루는지, 입력 상태가 성능에 어떤 영향을 주는지를 세 알고리즘이 각각 다른 방식으로 보여 준다.

그래서 이번 주차는 특정 정렬 하나를 잘 외우는 것보다, 세 정렬의 전략 차이를 비교하면서 정렬 전체를 보는 눈을 만드는 시간이 더 중요하게 느껴졌다.

### `안정성`, `제자리 정렬`, `입력 상태` 체크 포인트

이전에는 정렬을 보면 그냥 빠른지 느린지만 먼저 생각했는데, 이번 주차 이후에는 같은 결과를 내도 `안정적인가`, `추가 공간이 필요한가`, `이미 정렬된 경우에는 어떤가` 같은 질문을 같이 보게 됐다.

이 질문들이 생긴 것만으로도 정렬을 훨씬 더 자료구조답게 보게 됐다는 느낌이 들었다.

#### 동일 입력 비교 예시

```python
numbers = [29, 10, 14, 37, 13]

print(selection_sort(numbers))
print(insertion_sort(numbers))
print(bubble_sort(numbers))
```

세 함수 모두 결과는 같은 오름차순 리스트를 돌려준다. 그런데 내부에서 데이터를 다루는 방식은 완전히 다르다. 결국 자료구조에서 중요한 건 "무엇이 정답인가"만이 아니라 "그 정답에 어떤 방식으로 도달하는가"라는 점이 다시 한 번 드러난다.

## 기본 정렬을 먼저 배우는 이유

교안 후반의 문제와 정리 파트를 보고 있으면, 이번 주차가 단순히 시험용 개념 나열이 아니라는 생각이 든다. 선택, 삽입, 버블은 각각 단순하지만 정렬이 어떤 식으로 진행되는지를 가장 투명하게 보여 주기 때문이다.

### 정렬 구간 처리 방식 차이

선택 정렬은 정렬되지 않은 부분에서 최소값을 고르고, 삽입 정렬은 정렬된 부분 안에 새 값을 끼워 넣고, 버블 정렬은 전체를 훑으며 인접 원소를 계속 비교한다. 이 세 전략 차이만 제대로 잡아도 이후 복잡한 정렬을 볼 때도 훨씬 덜 낯설어진다.

즉 기본 정렬은 느린 알고리즘이라서 배우는 게 아니라, 정렬이라는 개념을 가장 해부하기 쉬운 형태로 보여 주기 때문에 먼저 배우는 셈이다.

### `정렬 결과`보다 중요한 `정렬 과정`

정렬은 결국 끝나고 나면 모두 같은 오름차순 리스트를 만든다. 그런데 자료구조 관점에서 더 중요한 건 그 결과에 도달하는 과정이다. 몇 번 비교했는지, 몇 번 움직였는지, 어느 경우에 강하고 약한지가 다 알고리즘의 성격을 만든다.

이번 주차를 지나며 남은 것도 바로 그 감각이었다. 정렬은 결과가 아니라 과정까지 같이 읽어야 하는 단원이라는 감각 말이다.

## 7주차 핵심 정리

이번 주차는 `정렬의 개념`, 여러 분류 기준, `선택 정렬`, `삽입 정렬`, `버블 정렬`까지 이어지며 정렬을 단순 반복문 문제가 아니라 전략 비교의 문제로 보게 만들었다.

같은 오름차순 정렬이라도 어떤 방식으로 정렬된 영역을 넓혀 가는지, 데이터를 얼마나 이동시키는지, 입력 상태에 얼마나 영향을 받는지에 따라 알고리즘은 전혀 다른 성격을 갖는다.

그래서 이번 주차를 지나며 정렬은 "순서를 맞춘다"보다 "어떤 비용으로 순서를 맞출 것인가"라는 질문으로 더 오래 남았다.

## 중간고사 정리 포인트

중간고사 준비를 하다 보면 자료구조 단원들이 따로따로 흩어져 보일 수 있다. 그런데 7주차 정렬을 기준으로 다시 보면 앞에서 배운 `배열`, `연결 리스트`, `탐색`, 그리고 `복잡도` 이야기가 전부 이어진다.

시험 정리 때도 `선택/삽입/버블`만 외우기보다 `정렬이 필요한 이유`, `정렬 분류 기준`, `안정성`, `제자리 정렬`, `입력 상태에 따른 차이`까지 한 흐름으로 묶는 편이 더 잘 남을 것 같다. 특히 세 기본 정렬의 아이디어와 특징 차이는 직접 표처럼 비교해 두면 훨씬 덜 헷갈릴 것이다.
